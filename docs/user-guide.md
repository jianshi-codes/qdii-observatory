# 用户指南

本页面向通过浏览器使用 QDII Observatory 的用户。安装、外部数据库和命令行细节分别见[快速开始](quickstart.md)、[外部 PostgreSQL](external-postgresql.md)和[运维手册](operations.md)。

## 1. 第一次打开

Docker 启动后访问 <http://127.0.0.1:5173>。首次安装没有基金是正常状态，不需要先准备 CSV 或数据库表。

主导航包含六个页面：

| 页面 | 用途 |
| --- | --- |
| 基金总览 | 筛选基金、查看最新披露与净值覆盖、进入详情或发起对比 |
| 收益看板 | 查看主动科技 QDII 核心/广义基金池的每日、MTD 和 QTD 正式净值收益 |
| 地区看板 | 查看主动科技 QDII 的季度直接披露或穿透地区分布及缺失覆盖 |
| 我的持仓 | 导入或维护本地持仓，查看定投、收益和一致性分析 |
| 基金对比 | 对比最多 5 只基金的暴露、持仓重叠和净值表现 |
| 数据运维 | 添加基金、补齐数据、查看任务进度、质量问题和来源状态 |

“我的持仓”入口和本地数据能力默认开启，首次启动时为空。若不需要该模块，设置 `QDII_ENABLE_PORTFOLIO=false` 并重启 backend 与 worker 后即可关闭持仓读写。

## 2. 添加基金

打开“数据运维”，选择一种入口：

- **公开基金目录**：基金公司、来源分类和研究领域是独立筛选条件，可以单独使用或组合使用；勾选后确认导入。
- **按基金代码添加**：输入六位代码，先核对公开名称、基金公司和分类，再确认导入。
- **批量文件导入**：下载 XLSX 模板，上传后先预览校验；只有点击“确认导入”才会写入数据库。

同一基金合同的 A/C、人民币/美元等份额会归并展示，但净值和申购限额仍按份额保存。重新导入已归档基金会恢复原记录，不会重复创建。

## 3. 为新基金准备数据

新增基金后，在“数据准备向导”的“只补齐所选基金”中选择它，再点击“按本季度补齐全部阶段”。该任务会依次：

1. 从当前季度首日补净值；场内基金同时补价格。
2. 刷新当前可验证的申购限额和估值所需汇率。
3. 获取最近已结束季度的报告。
4. 解析股票、基金、国家和行业披露。
5. 计算可解析的基金穿透关系。

如果只缺少近期净值，选择 5、10 或 30 个日历日后使用“补历史净值”。全部基金的维护按钮分成三组：

| 分组 | 适合什么时候使用 | 包含内容 |
| --- | --- | --- |
| 每日数据 | 日常维护或来源短暂失败后重试 | 净值、场内价格、当前限额、汇率 |
| 本季度数据 | 新基金落地或季度内出现缺口 | 从本季度首日起补每日数据 |
| 季度报告 | 新报告发布后，每个报告期一次 | 下载报告、解析持仓、计算穿透 |

浏览器提交后只创建持久化任务，独立 worker 执行网络抓取和 PDF 解析。可以刷新页面或离开页面，任务不会因此取消；同一时间只运行一个数据操作。

## 4. 理解基金总览与详情

基金总览支持搜索，并可按持仓状态、基金公司、来源分类、研究领域和科技细分口径筛选。持仓基金使用更明显的行背景；已归档基金不计入活跃基金数和后续同步。

点击基金名称进入详情页，可以查看：

- 基金合同与全部份额代码；
- 季度报告、解析置信度和来源证据；
- direct 与 look-through 国家、行业、股票和基金持仓；
- 官方净值、场内价格、申购限额和每日涨跌幅；
- 解析失败或低置信度问题及可用溯源链接。

页面中的 `—` 表示没有可验证数据，不等于 0。官方净值和场内价格不会互相替代。

## 5. 常见状态是什么意思

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 数据源 `UNKNOWN` | 进程启动后尚未对该 Provider 发出真实请求 | 运行一次相关同步后再判断；未请求不等于故障 |
| 任务“部分完成” | 已有部分结果，但某些基金、份额或来源失败 | 展开质量问题，按中文分类查看基金代码和来源链接 |
| “部分穿透” | 已解析一部分基金持仓，但仍有目标基金未匹配或缺少可用报告 | 查看未解析基金持仓，再补目标基金报告或映射 |
| `INSUFFICIENT_DATA` | 观测天数、报告覆盖或代理数据不足 | 按提示补历史净值或配置可追溯代理，不应强行估算 |
| 解析低置信度 | 找到了候选表格，但结构、列名或总计校验未达到可靠阈值 | 打开来源 PDF 核对，并保留问题供解析器修复 |

质量问题在 UI 中按中文类型折叠，内部英文错误码用于排障和测试，不要求普通用户逐条阅读。

## 6. 基金对比

在基金总览勾选 2–5 只基金后点击“对比所选”。对比页展示国家、行业、前十大持仓、净值走势和相关性。

不同基金的披露日期或净值日期可能不同。页面会显示实际数据日期；不要把缺失数据当作 0，也不要把季度披露当作当前真实仓位。

## 7. 我的持仓与定投

“我的持仓”默认可以：

- 下载 XLSX 模板，预览校验后确认导入；
- 在持仓表底部手动新增持仓；
- 修正用户提供的份额、成本、参考市值、累计收益等字段；
- 刷新净值，并处理已有定投计划。
- 运行持仓一致性后，预览并复制 AI 分析 JSON 或完整 ChatGPT 提示词。

持仓估值以**用户确认的份额**为主导，金额和收益字段是辅助校验。来源提供的最新净值、涨跌幅和报告数据不可在 UI 中手工覆盖。

定投先记录为待确认订单：重复刷新不会重复创建同一计划、同一交易日的订单。只有取得适用净值并完成确认后，份额、本金和持仓市值才会变化；T+1/T+2 是确认进度，不应提前伪装成已成交。详细隐私与字段边界见[持仓隐私](portfolio-privacy.md)。

“导出 AI 分析”不会自动调用外部服务。JSON 保留总资产、各持仓金额与份额、收益、费率、定投金额、现金流和备注，同时删除平台名以及本地持仓、基金和重叠关系的数据库 ID。复制到 ChatGPT 后，个人财务数据会离开本地应用；生成的提示词要求先核对日期与覆盖、区分事实和推断、不给出保证收益或直接交易指令，并在个性化建议前补问期限、风险承受能力、流动性与税务约束。

## 8. 主动科技 QDII 看板

“收益看板”提供核心 18 只和“核心 + 动态”33 只两种基金池，可切换每日、月初至今（MTD）和季初至今（QTD），并按收益、净值滞后或代码排序。指标在请求时读取正式净值计算；每日同步完成后刷新页面即可更新，不会另建指标快照表。

页面同时显示同步日期、最新正式净值日期和共同可比日期。累计净值在区间首尾均可用时优先采用，以纳入分红影响；缺少净值、缺少区间基准和净值滞后会单独标记，不会填成 0。

“地区看板”按季度展示基金地区堆叠、基金池平均分布和缺失覆盖，可切换直接披露（DIRECT）与穿透（LOOKTHROUGH）。地区平均值只以有地区数据的基金为分母，不补齐单只基金未披露权重。

两个页面的“导出整页 PNG”均在浏览器本地生成图片，不调用远程截图服务。收益看板固定为 1440×2200，地区看板固定为 1440×2400；导出内容包含来源日期和风险提示。详细口径见[主动科技 QDII 看板](active-tech-dashboards.md)。

## 9. 归档与恢复基金

在基金总览或基金覆盖情况中点击“归档”，基金会退出 active universe 和后续同步，但历史净值、报告、限额和分析不会删除。

之后从公开信息或持仓导入再次添加同一基金时，系统会从 archive 恢复原记录。恢复后再按实际缺口补数据即可。

## 10. 日常维护

通常只需在“数据运维”中运行每日同步，并查看任务是否为“已完成”或“部分完成”。新季度报告发布后，再执行一次报告下载、解析和穿透。

停止、重启、更新代码、备份和恢复的完整步骤见[每日维护与重启](daily-operations.md)。遇到 HTTP 500、任务停滞、空库或 Provider 失败时见[故障排查](troubleshooting.md)。

## 11. 隐私与安全

项目默认绑定 `127.0.0.1`，不内置遥测，也不会自动上传数据库或持仓文件。启用公开 Provider 后，查询所需的基金代码和请求参数会发送给对应来源。

不要把真实持仓、`.env`、数据库、备份、原始响应、cookie、token 或未脱敏截图提交到 Git。准备公开 Issue 或文档截图时，请使用仓库内的 synthetic demo。
